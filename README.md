# «Моя Библиотека»

## 1. Анализ 

### Ключевые вызовы и неэффективность
В современном мире у пользователя накапливается много контента разных форматов. Это могут быть бумажные книги, PDF и EPUB-файлы и аудиокниги.

Без единой системы контроля возникают следующие проблемы (неэффективности):
* Хаос в учете: Сложно быстро вспомнить, какие книги уже куплены в бумаге, какие скачаны, а какие только планируются к изучению.
* Потеря прогресса: Нет фиксации текущего статуса («В планах», «Читаю», «Прочитано»). Из-за этого сложно контролировать свои списки учебной или личной литературы.
* Отсутствие аналитики: Невозможно наглядно оценить структуру своей библиотеки (какие жанры преобладают, сколько книг реально дочитано до конца).

### Влияние проблемы и актуальность
Для пользователя эта проблема несет временные потери и снижение качества обучения:
1. Временные затраты: Тратится лишнее время на поиск нужного файла книги на диске или повторный поиск информации в интернете.
2. Финансовые риски: Покупка дубликатов бумажных книг из-за того, что забыл о наличии книги дома.
3. Снижение продуктивности: Отсутствие четкой структуры снижает мотивацию к саморазвитию и учебе, так как «в планах» скапливается неконтролируемый завал литературы.

### Организационный контекст
Данная проблема возникает в процессе повседневного самообразования, подготовки к учебным занятиям или организации досуга. На это влияет человеческий фактор (забывчивость, отсутствие привычки вести учет) и технологические особенности (многообразие форматов и устройств для чтения).

Приложение «Моя Библиотека» выступает в роли единого цифрового центра для организации и систематизации этого процесса.

## 2. Обзор существующих решений

| :--- | :--- | :--- | :--- | :--- |

### Аргументация выбора предлагаемого подхода

Анализ аналогов показал, что существующие системы либо избыточны (соцсети, реклама, подписки), либо требуют от пользователя навыков проектирования баз данных (Notion). 

**Выбор стека разработки (Spring Boot + Thymeleaf + H2 DB):**

1. Архитектурный контроль: Использование Java и Spring Boot позволяет создать строго структурированную систему (MVC), где логика обработки жанров, тегов и форматов полностью контролируется разработчиком.
2. Динамическая аналитика: В отличие от Excel, где пользователю нужно вручную настраивать формулы, сводные таблицы и диаграммы для каждой новой записи, разработанное приложение полностью автоматизирует этот процесс. Слой бизнес-логики самостоятельно выполняет SQL-запросы к базе данных при каждом обновлении страницы. Программа сама группирует книги по жанрам, подсчитывает процентное соотношение форматов и мгновенно передает готовые массивы данных во фронтенд для отрисовки графиков.
3. Автономия: Локальный запуск (через веб-интерфейс `localhost`) гарантирует конфиденциальность данных, высокую скорость отклика и независимость от внешних факторов, интернета или подписок.

## 3. Концепция решения

### Суть предложенного метода и общий принцип действия
В основе решения лежит концепция автономного локального веб-приложения. Вместо сложной установки полноценного веб-сервера и развертывания тяжелых баз данных, проект запускает всю инфраструктуру внутри персонального компьютера пользователя.

**Общий принцип действия:**
1. Пользователь запускает приложение. Программа локально поднимает веб-сервер и подключается к изолированной базе данных.
2. Все взаимодействие происходит через привычный интерфейс веб-браузера по адресу `http://localhost:8080/`.
3. Приложение берет на себя всю рутину: валидацию данных, автоматическое связывание книг с тегами и жанрами, а также мгновенный расчет статистики.

---

### Основные компоненты системы

Архитектура системы построена по классическому шаблону MVC (Model-View-Controller) и разделена на три логических слоя:

1. Слой представления (View):
   * Разработан на базе HTML-шаблонов Thymeleaf и стилизован с помощью Bootstrap/CSS.
   * Отвечает за отображение веб-страниц, динамические формы добавления книг, фильтры и интерактивные графики аналитики.
2. Слой бизнес-логики и контроллеров (Controller & Service):
   * Написан на Java с использованием фреймворка Spring Boot.
   * Контроллеры принимают запросы пользователя из браузера, а сервисы обрабатывают данные: фильтруют списки, группируют книги и считают математические показатели для графиков.
3. Слой хранения данных (Model):
   * Использует технологию Spring Data JPA (Hibernate) для управления данными.
   * База данных является встроенной, что исключает необходимость настройки внешних СУБД.

---


### Ключевые преимущества решения

* Нулевая стоимость владения и приватность: Данные не уходят на серверы сторонних компаний, что полностью исключает риски утечек, блокировок или введения платных подписок.
* Отсутствие рутины при анализе данных: Пользователю больше не нужно вручную вести таблицы. Приложение само группирует информацию.
* Портативность: Благодаря встроенным компонентам, всю программу вместе с базой данных можно перенести на флешку и запустить на другом компьютере без потери данных и повторной настройки.

## 4. Архитектура решения и детализация внедрения

### Спецификация компонентов и стек технологий (Технические характеристики)

Приложение является полностью автономным и не требует предварительной установки сторонних серверов баз данных или веб-серверов. Все необходимые компоненты инкапсулированы (встроены) внутрь исполняемого модуля.

* Среда выполнения: Java Development Kit (JDK) версии 17 или выше.
* Бэкенд-платформа: Spring Boot 3.x.
* Слой доступа к данным: Spring Data JPA / Hibernate.
* База данных: Встроенная СУБД H2 Database.
* Фронтенд-компоненты: HTML5, CSS3, шаблонизатор Thymeleaf, CSS-фреймворк Bootstrap 5.
